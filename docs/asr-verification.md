# 받아쓰기 검증 기록 — Groq 파이프라인 (2026-10-05)

브랜치 `fix/low-memory-asr`, 기준 커밋 `e098f94`. 받아쓰기를 브라우저 Whisper에서 Groq(`whisper-large-v3-turbo`)로 옮긴 뒤(커밋 `5566eaf` 이후)의 검증 상태다. 측정 환경은 모두 같은 PC(Core Ultra 5 225H, 16 GB, Intel Arc 130T)다. 구 브라우저 Whisper 검증은 맨 아래 "역사"로만 남겼고 현재 코드에는 해당하지 않는다.

## 1. 검증 대상 구조

강의 mp4를 HTTP Range로 구간씩 받아(`offscreen.js`, `media.js`) AAC를 디코딩 없이 M4A로 묶고(`aac.js`), 네이티브 호스트(`native-host/host.mjs`, `groq.mjs`)를 거쳐 Groq로 보낸다. 호스트는 요청마다 새로 실행되고 응답 후 연결이 끊긴다(`background.js` `nativeCall`). 확정 110초 + 꼬리 10초를 보내고 다음 구간은 마지막으로 저장한 발화 끝에서 시작한다(`window.js`). 숫자가 든 발화는 앞뒤 3초를 붙여 다시 받아쓰고(`numcheck.js`), 환각이 의심되는 구간은 지우지 않고 표시한다(`suspect.js`, `report.js`). Groq 키는 호스트 폴더의 `groq-config.json`에 저장되며 이 문서는 키를 다루지 않는다.

## 3. 실제 Groq·실제 강의 검증 (2026-10-05)

속도·자원
- Groq turbo는 30초 클립당 0.6–1.1초.
- Groq 호출 클라이언트 프로세스의 최대 RSS 64 MiB.
- 네이티브 호스트 콜드 스타트 약 130 ms(요청마다 새로 띄워도 부담이 작다는 근거).
- 실제 확장으로 강의를 처리하는 동안 Chrome 전체 CPU 평균 1.9%, 최대 5.3%(확장 프로세스 0.3–2.8%). Chrome 메모리 1.4–1.9 GB이며 처리 중 증가하지 않았다. 구 브라우저 Whisper 실행(아래 역사)의 Chrome 메모리 증가 약 1.7 GB와 대비된다.

경계·환각·숫자
- 이어 붙인 실제 강의 처리에서 창 경계의 문장 누락·중복이 없었다.
- 무음에서 생긴 환각 "자막제공자"가 꼬리 규칙(`commitWindow`)으로 버려졌다. 이전 단계의 실제 large-v3 응답 재생에서는 30초 클립 끝 0.14초에 앞 문장을 다시 지어낸 사례가 있었고, 같은 규칙이 이를 버렸다.
- 의심 표시 기준은 실제 강의의 Groq 114구간에서 나왔다. 정상 발화는 초당 2.9–11자, 끝에서 지어낸 문장은 초당 128.6자였다. 무음 10초에서 turbo와 large-v3 모두 "감사합니다."를 만들었다. 114구간 재생에서 알려진 환각 3건만 표시되고 정상 발화는 표시되지 않았다. `no_speech_prob`는 turbo가 환각 구간에도 0.000이어서 쓰지 않는다.
- 숫자: 같은 강의 구간을 단독 30초 클립으로 3회 받으면 "출석의 10%", 앞에 무음이 붙은 이어 받아쓰기는 "20%"로 바뀌었다. 숫자 재확인이 20% 구간을 표시했고, 맞는 숫자 발화 2건은 표시하지 않았다.
- 군말 제거(`compact`)가 줄이는 양은 실제 Groq 출력에서 1.2%여서 AI에는 군말을 덜지 않은 원문을 보낸다.

## 4. 한계와 미검증

- 같은 모델로 다시 받아쓰는 숫자 재확인은 같은 오류를 반복할 수 있다. 어느 쪽이 맞는지는 판단하지 않는다.
- 숫자 재확인은 아라비아 숫자만 본다. 한국어 수사("십 퍼센트")는 검사하지 않는다.
- 무음 직후 구간의 타임스탬프가 무음 길이를 흡수할 수 있다. 그 경우 슬라이드와 발화가 어긋날 가능성이 있다(미검증).
- 새 프롬프트(`lecture-points-v2`, 발화 단위 교정, 숫자 재확인 안내)로 한 AI 요약의 처음부터 끝까지 검증은 아직 없다. 개인 지침 로딩과 모델의 준수 여부도 유료 호출로 확인하지 않았다.
- 설치된 확장의 전체 E2E(받아쓰기 → 확인 → AI 요약 → 다운로드), 실제 KLAS 목록의 행 매핑, KLAS Helper와의 동시 사용, 실제 Mac 기기는 미검증이다.
- Claude Code CLI는 `claude-opus-5-5`를 쓰려면 2.1.280 이상이 필요하다(2026-10-05에 2.1.289로 갱신).
- Groq 무료 한도(분당 요청 수 등)에 걸리면 `GROQ_RATE_LIMIT`로 대기했다가 자동 재개하게 되어 있다(`offscreen.js`). 실제 한도 도달 상황에서 이 재개 동작을 확인한 기록은 없다.

## 5. 요약노트 버튼과 사용자 요약 규칙 (2026-10-04 검증, 구조 변경 후 재검증 안 함)

- 확장에서 만든 HTML 상단의 '요약노트 만들기'는 저장된 강의 ID를 `note-launch.html`로 넘겨 기존 전송 확인 화면을 연다. iframe·잘못된 강의 ID는 거부하며, 요약 준비에는 AI 모드·동의·완료된 받아쓰기가 필요하다. 중단되거나 삭제된 강의를 자동 재처리하지 않는다. 합성 HTML에서 버튼·링크·보기 전환을 확인했고(테스트 `report-note.test.mjs`), 설치된 확장에서 실제 CLI 요약까지 가는 전체 경로는 미검증이다. 이미 받은 HTML에는 반영되지 않으므로 다시 받아야 한다.
- Claude 실행은 개인 설정(`--setting-sources user,project,local`)과 전역 CLAUDE.md를 로드하고 요약 지침은 사용자 입력으로 전달한다. 도구·MCP·자동 훅은 막는다. Codex도 개인 설정을 유지하고 도구만 끈다. 요약 문체·분량은 개인 규칙을 따르며 파서는 길이·항목 수를 자르지 않는다(전체 응답 크기·교정 한도·HTML 이스케이프는 유지).

## 이전 브라우저 Whisper 검증(역사)

아래는 2026-10-04까지의 브라우저 Whisper(transformers.js/ONNX, Chrome WebGPU) 기록이다. 해당 코드는 삭제되었고 현재 구조의 근거로 쓰지 않는다. 당시 측정은 `tools/engine-harness.html`로 실제 미디어·WebCodecs·Whisper·WebGPU·IndexedDB를 쓴 것이며 확장 offscreen·네이티브 메시지·AI 요약·다운로드 E2E를 대신하지 않는다.

- 모델: 한때 small 기본에서 사용자 승인으로 base 기본(단일 모델, 선택한 강의만 처리)으로 바꿨다. base GPU decoder는 q4에서 반복과 생성 한도 오류가 재현되어 fp16으로 높였다. `whisper-large-v3-turbo`는 이 PC에서 `std::bad_alloc`으로 실패했다.
- 안정성 작업: 로드·전사·해제 직렬화, 취소 시 worker 즉시 종료, 다른 강의 재시도는 FIFO 대기열, 다음 압축 구간 하나만 미리 받기(32 MiB 상한), 반복 생성 감지와 구간 반쪽 재시도. 당시 Node 테스트 76/76 통과(모델·GPU 미사용 회귀 테스트).
- 실제 Chrome 결과(base/fp16): Orientation 2810.27초(46분 50초)를 처음부터 끝까지 716.7초(11분 57초)에 완료(RTF 0.255, ASR 요청 합계 636.46초, 구간당 11.81–33.54초). 24개 구간, 전사 640개, 슬라이드 29개, 원문 18,632자, 시간 순서 유지. 이전 small 실행과 환경이 같지 않아 개선 배수는 주장하지 않았다. 초기 base/q4의 120초 구간 전사는 약 28–80초였다.
- 반복 오류: 기존 HTML의 12:18 문단에서 인사 구절이 222회 반복되던 구간을 다시 전사하자 해당 인사가 0회였다(반복 문제 검증이며 정확도 보증 아님).
- Chrome 전체 프로세스 메모리 샘플(최종 실행 중): Working Set 3,134,771,200 바이트, Private 2,739,298,304 바이트. 종료 후 Working Set 1,379,397,632, Private 1,051,586,560 바이트. 사용자 탭·GPU 프로세스를 포함하므로 모델 자체 사용량이나 통제된 개선율로 해석하지 않았다. 이 차이는 약 1.7 GB이며, 이후 받아쓰기를 Groq로 전환했다.
- 이 검증에서 AI 호출은 없었다(토큰 0).
