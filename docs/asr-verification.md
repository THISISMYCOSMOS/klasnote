# 받아쓰기 안정성·메모리 검증 — 2026-10-04

## 이번 변경

사용자가 승인한 base 기본값, 단일 모델, 현재 작업 우선 처리, 선택한 강의만 노트 생성 방식으로 변경했다. 예전의 두 worker 병렬 실험은 기본 처리 방식으로 사용하지 않는다. 저장된 small 설정은 유지하며, 설정에서 base를 선택할 수 있다.

- 로드·전사·해제와 worker 명령을 직렬화하고 실패·중지 후 worker를 종료한다. 대기 강의가 있으면 같은 모델을 재사용하고, 대기열이 비면 즉시 해제한다.
- 다른 강의의 재시도는 FIFO 대기열에 추가하며 현재 강의를 선점하지 않는다. 같은 강의의 중복 등록을 막는다.
- 영상·메타데이터 요청, 재시도 대기, 디코더 flush를 취소한다. 취소 뒤 늦은 PCM·bitmap 결과는 저장하지 않는다.
- 현재 받아쓰기와 다음 압축 구간 하나의 다운로드만 겹친다. 프리페치 데이터는 32MiB로 제한하며 HTTP 200 전체 응답, 선언 크기 초과, 실제 스트림 크기 초과를 거부한다. 다음 구간의 PCM·슬라이드·추가 모델은 미리 만들지 않는다.
- 받아쓰기 완료는 로컬 저장까지만 수행한다. 로컬/AI 모드와 전송 확인 설정에 관계없이 완료만으로 노트·AI 호출·HTML 다운로드·CLI 감지를 시작하지 않는다.
- 수백 번 이어지는 생성 반복과 토큰 한도에 걸린 불완전 결과를 감지한다. 같은 모델로 해당 조각의 정확한 두 반쪽을 한 번씩 재시도하며, 여전히 실패하면 그 구간 전체를 저장하지 않는다. 반복 오류의 복구 호출에만 6토큰 연속 재생성 제한을 적용한다. 정상 전사와 생성 한도만 넘긴 재시도는 제한하지 않으며, 전사 텍스트를 사후 삭제하지 않는다.
- 모델 진행률은 다운로드 바이트를 합산하며 역행하지 않는다.
- base의 GPU encoder·decoder는 fp16을 사용한다. small의 decoder는 q4, CPU는 q8을 유지한다. base/q4에서 실제로 반복과 생성 한도 오류가 재현되어 base GPU decoder의 기본 정밀도를 높였다. 같은 모델 하나만 사용한다.

## 로컬 검증

npm test: **70/70 통과**. 모델/GPU를 쓰지 않는 회귀 테스트이며 실제 브라우저 검증과 구분한다.

검증 범위: 모델 수·직렬 처리·해제 실패 복구, 반복/생성 한도·시간 범위, FIFO·중복 재시도·취소 후 재개·새 엔진 재개, 다운로드/디코딩 취소·늦은 결과 폐기, 프리페치 응답 크기 제한, 완료만으로 AI/노트를 생성하지 않는 계약과 명시적 로컬 HTML 생성.

독립 서브에이전트 검토가 재현한 디코딩 취소 지연과 HTTP 200 프리페치 한도 우회를 수정했다. 통합 계약의 추가 중대한 회귀는 발견되지 않았다.

## 실제 Chrome 검증

실제 Chrome에서 tools/engine-harness.html로 실제 미디어·WebCodecs·Whisper base·WebGPU·IndexedDB를 사용했다. 하네스는 확장 runtime을 대신하는 개발 도구이므로 Chrome 확장 offscreen·네이티브 메시지·AI 요약·실제 다운로드 전체 E2E를 대체하지 않는다.

- Orientation 처리 중 다음 강의 등록과 현재 강의 중복 재시도를 실행했다. Orientation이 계속 실행되고 다음 강의 하나만 대기했다.
- 320.0초에 현재 강의를 중지하자 worker가 즉시 0개가 되었고, 320.3초에 다음 강의가 준비를 시작했다. 취소된 강의는 paused, 저장 진행 720초였다.
- 페이지를 다시 열어 새 엔진으로 저장된 마지막 슬라이드 끝 708.799초에서 재개했다. 기존 저장 데이터를 기반으로 실행하며 worker 하나만 사용한다.
- 소개1의 12:00–13:00 구간을 실제로 다시 전사했다. 기존 HTML에는 12:18 문단의 인사 구절 222회 반복이 있었지만 새 구간 텍스트 440자에는 해당 인사 0회였다. 반복 문제의 검증이며 전사 정확도 전체를 보증하지 않는다. 이 강의는 테스트 목적의 840초까지 처리 후 중지했다.
- 최초 복구 방식으로는 Orientation의 1308.799초부터인 구간에서 반복이 지속되어 명시적 ASR_REPETITION 오류가 발생했다. 잘못된 구간은 저장하지 않았고 다음 강의가 시작됐다. 복구 호출 제한을 보완한 q4 실행에서도 1535.666초 구간에 생성 한도 오류가 재현되어 base GPU decoder의 정밀도를 높였다.
- 최종 base/fp16 설정으로 Orientation 2810.27초(46분 50초)를 **처음부터 끝까지 716.7초(11분 57초)**에 완료했다. 모델 캐시가 있는 같은 PC의 실제 Chrome 하네스 측정이다. 24개 구간, 전사 640개, 슬라이드 29개, 원문 18,632자이며 시간 순서가 유지됐다. 최종 실행의 전사 실패·GPU 재시도·destroy 오류 없음. 완료 즉시 worker 0개, 실행·대기 목록 모두 비어 있음.
- 완료 후 로컬 보고서 버튼을 눌러 HTML 생성 성공과 보고서 제목의 새 탭 생성을 확인했다. blob 보고서의 내용 열람은 브라우저 제어 도구의 URL 정책에 차단되어 시각적 내용 검사는 하지 못했다. 실제 확장 다운로드 E2E로 주장하지 않는다.

## 속도·메모리 측정 한계

초기 base/q4의 120초 구간 전사 시간은 79.75, 31.99, 29.86, 55.46, 27.68, 29.79초였다. 첫 구간의 준비 영향을 포함하며 구간 발화 내용에 따라 달라진다. 재개 후 첫 세 구간은 23.00, 26.21, 28.65초였다. 이전 small 실행과 환경·준비 상태가 완전히 같지 않아 모델 교체만으로 몇 배 빨라졌다고 주장하지 않는다.

짧은 base/fp16 비교에서는 25.37, 30.68, 25.47, 30.17, 31.27초였다. 구간별 차이가 일정하지 않아 이 비교만으로 채택하지 않았다. 이후 q4에서 지속된 생성 오류가 재현되어 안정성 검증을 위한 base GPU 기본값을 fp16으로 변경했다. 일반 모델 로더의 정밀도 선택을 사용하며 하네스 전용 dtype 강제 코드는 제거했다.

fp16 재개 실행은 이전 생성 한도 오류 구간을 포함한 1470.334초부터 1830.334초까지 통과했다. 별도 base-fp16-final-whole 실행은 처음부터 끝까지 완료했다. ASR 요청 시간 합계는 636.46초, 구간당 11.81–33.54초(마지막 구간은 50초 분량), 전체 처리 RTF는 0.255였다. 이는 현재 PC의 실측이며 이전 small의 통제된 전체 강의 비교가 없어 개선 배수를 제시하지 않는다.

Chrome 전체 프로세스 합계 샘플: 최종 base/fp16 실행 중 Working Set 3,134,771,200바이트, Private 2,739,298,304바이트. 종료 후 Working Set 1,379,397,632바이트, Private 1,051,586,560바이트였다. 프로세스 수는 11→12로 달랐으며 사용자 탭·GPU 프로세스도 포함하므로 모델 자체의 메모리 사용량이나 통제된 개선율로 해석하지 않는다. worker 종료와 OS 메모리 회수를 각각 관찰했다.

## 재현과 미검증 범위

node tools/devserver.mjs 후 http://localhost:8787/tools/engine-harness.html?id=<contentId>&run=<검증명>&model=base&next=<다음contentId>에서 실행한다. KLAS 뷰어나 출석·진도 API는 열지 않는다. 메타데이터·미디어 Range만 읽고 검증별 별도 IndexedDB를 사용한다. 로그는 tmp/spike-out/engine-<검증명>.log에 저장한다.

실제 확장 오류의 원본 ORT 스택은 확보하지 못했다. 따라서 lifecycle 수정이 보고된 destroy 오류의 원인을 확정했다고 주장하지 않는다. 실제 확장 전체 E2E와 실제 Mac 검증은 여전히 별도다.

이번 검증의 AI 호출 없음. AI 입력·출력 토큰 **0**. 기존 사용자 HTML에 기록된 과거 AI 사용량은 이 수치에 포함하지 않는다.
