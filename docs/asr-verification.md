# 받아쓰기 안정성 검증 — 2026-10-04

## 로컬 수정과 회귀 테스트

- 모델 로드·전사·해제를 같은 큐에서 실행한다. 해제는 진행 중인 전사의 모든 조각이 끝날 때까지 기다린다.
- 해제 실패가 이후 로드를 계속 실패시키던 Promise 체인을 복구하고, 이미 해제된 모델 핸들의 재사용을 거부한다.
- 중복 로드는 모델을 공유하고, decoder dtype 변경은 새 모델을 사용한다.
- 파일별 다운로드 바이트를 합산하고 표시가 역행하지 않게 한다. 파이프라인 `ready` 이전에는 100%를 표시하지 않는다.
- 기존 코드에서 실패하는 lifecycle 회귀 테스트 6개를 먼저 확인했다. 수정 후 기존 29개와 새 8개, 총 37개가 통과했다.

## 병렬 브랜치에서 추가한 검증

- worker 명령 전체(재시도 포함)를 직렬화한다. 실패한 worker의 원본 스택을 offscreen 콘솔과 개발 하네스에 전달한다.
- 로드 실패·로드 중 취소 시 등록되지 않은 worker를 남기지 않는다. 취소와 오류 시 모든 worker를 종료한다.
- 재생 중 유휴 두 번째 worker를 종료하고, 실행 중인 두 번째 worker는 현재 작업을 마친 직후 종료한다.
- 미확정 구간을 종료·정리한 뒤 다음 강의를 시작한다. 취소된 worker의 늦은 응답을 저장하지 않는다.
- 순서가 뒤집힌 전사 응답의 저장 순서, 취소 후 재개, 새 엔진에서 저장 지점 재개, CPU 단일 worker, 최대 2개 제한을 작은 mock으로 검증했다.
- 병렬 브랜치의 Node 테스트는 총 43개 통과했다. 모델·GPU·실제 미디어를 사용하지 않는 회귀 테스트이며, 전체 강의 성능 검증은 아니다.

## 브라우저 관찰과 한계

- Codex 앱 내 브라우저에서 GPU 어댑터 확보를 확인했다.
- 원본 main 엔진은 강의 시작부터 3개 구간(6분, 약 10%)을 전사했다. 원본 worker 브랜치도 단일 worker로 같은 범위를 전사했다.
- 이 부분 실행에서는 `destroy` 오류를 재현하지 못했다. 오류 스택은 아직 확보하지 못했으므로, lifecycle 수정이 보고된 ORT 오류의 원인을 해결했다고 주장하지 않는다.
- 모델 다운로드 진행률의 역행은 실제로 관찰했다. 수정된 진행률의 실제 다운로드 검증은 미완료다.
- 첫 테스트 탭 종료는 사용자의 메모리 부담으로 인한 종료였으며 브라우저 충돌 증거가 아니다. 이후 재현 탭도 종료했다. 대형 모델을 재실행하지 않는다.
- 전체 강의 완료, 실제 Chrome offscreen/worker 콘솔, 1개/2개 worker 처리량과 최대 메모리는 미검증이다. 병렬 브랜치는 main에 병합하지 않는다.
- AI 호출 없음. AI 입력·출력 토큰 사용량 0.

## 재현 도구

`node tools/devserver.mjs` 실행 후 `http://localhost:8787/tools/engine-harness.html?id=<contentId>&run=<검증명>`에서 실제 offscreen 엔진을 실행한다.

- KLAS 뷰어나 출석·진도 API를 열지 않는다. 영상 메타데이터와 미디어 Range 읽기만 수행한다.
- `run`별 별도 IndexedDB를 사용하여 기존 강의 기록과 분리한다.
- worker 진단 메시지와 offscreen 콘솔 스택을 화면에 표시한다. 로그는 `tmp/spike-out/engine-<검증명>.log`에 저장된다.
- worker 브랜치에서 `one=1`은 playerAlive 신호로 1개를 강제한다. `model=base`는 더 작은 모델을 선택한다.
- 하네스는 실제 Chrome 확장·네이티브 메시지·AI 요약·다운로드 E2E 검증을 대체하지 않는다.
