# 검증 상태 — 2026-10-04

## 로컬 중복 방지와 상태 표시 — 2026-10-07

- Drive 작업은 사용자 요청으로 보류했다. 이번 변경은 로컬 HTML 다운로드, 중복 처리 요청, 프론트 표시와 README 다운로드 링크에 한정했다.
- 전체 Node 테스트 137개 통과. 동시 다운로드 합치기, 다른 원문·요약 요청 분리, 기존 동일 파일 재사용, 삭제·내용 변경 시 재저장, 완료·중단·삭제 이벤트 표시, 처리 요청 중복 방지, 이전 저장본 표시를 검증했다. 수정한 JavaScript 문법 검사와 diff 공백 검사도 통과했다.
- 같은 강의의 동시 다운로드 요청을 한 번으로 합친다. 생성한 HTML의 SHA-256과 이전 Chrome 다운로드의 완료·파일 존재를 비교해 동일 파일을 재사용한다. 삭제·중단·변경된 파일은 다시 저장하며 원문·요약 파일명을 분리한다.
- 처리 요청 중복과 받아쓰기 완료 후 재처리를 막는다. 내 강의 기록의 기본 요약 버튼은 저장된 결과를 재사용하고, 기존 새 요약 생성 기능은 별도 명시적인 버튼으로 유지한다.
- 목록·패널·설정에 작은 로컬 저장 표시를 넣었다. 처리 중 버튼 비활성화, 화면 갱신 중 요청 잠금 유지, 원문·요약 표시, 저장 중단·이전 저장본·재다운로드 안내를 확인했다.
- headless Chrome에서 가상 강의 데이터와 실제 UI 스크립트로 확인했다. 클릭·상태 변경·800px 배치·기존 요약 재사용과 명시적인 새 요약 선택 검증이 통과했다. 실제 KLAS 접속이나 설치된 확장으로 강의 전체를 처리한 검증은 아니다.
- GitHub API로 기존 ZIP 파일(1,214,826 bytes, SHA 0b3b37b688b3790f6d3f389c205781cb38b6cf6f)의 존재를 확인하고, 동일한 로컬 ZIP의 압축 목록을 읽었다. README 링크는 API가 제공한 직접 다운로드 주소로 변경했다. 사용자가 본 실제 다운로드 실패 문구는 없어서 실패 원인은 확정하지 않았다. 기존 ZIP과 GitHub 원격 소스는 이번 작업으로 갱신하지 않았다.

## 선택 Google Drive 백업 — 2026-10-07 (보류)

- 전체 Node 테스트 130개 통과. 새 Drive 모의 API 테스트는 다운로드 완료 조건, 중복 방지, 원문·요약본 분리, 실패 재시도, 중단·재시작, 계정 변경·401 이후의 잘못된 계정 전송 방지, 파일 삭제·휴지통 상태를 확인한다.
- 별도 headless Chrome의 샘플 페이지에서 강의 목록·설정·패널의 작은 백업 표시, 재시도 클릭, 기본 꺼짐, 계정 연결만으로 백업이 켜지지 않음, 설정 저장 분리, OAuth 미설정 안내, 좁은 화면 배치, KLAS 기본 버튼의 글자 크기·모서리 스타일을 확인했다. 실제 KLAS 페이지나 설치된 확장 환경을 검증한 결과는 아니다.
- 실제 브라우저 IndexedDB에서 v1의 기존 강의 기록을 보존한 채 v2로 업그레이드하고, 백업 Blob의 UTF-8 내용 저장·읽기·해제를 확인했다.
- OAuth 클라이언트 ID 미제공: 실제 Google 로그인·업로드·계정 전환·Drive 원격 조회는 미검증. [설정 안내](google-drive-setup.md)에 최초 설정과 실제 연결 확인 절차를 기록했다.
- 기존 배포 ZIP은 수정하지 않았다. 아래 2026-10-04 기록은 이전 검증이며 이번 작업의 증거와 구분한다.

- 기존: Node 테스트 16개, 합성 브라우저 데이터 검사 8개, 실제 Chrome 154 확장 등록·서비스 워커·저장소 재연결 유지 통과.
- 이번: 백엔드 14개 + 설치 안전성 3개 통과. 설치 필수 파일과 번들 라이브러리 존재 확인.
- 새 설치 프로그램의 실제 레지스트리 등록·Chrome 화면 열기까지는 실행하지 못했음. 기존 PowerShell 설치·현재 사용자 네이티브 호스트 CLI 감지는 이전 검증에서 통과.
- 실제 Chrome 패널 시각 동작, 강의 전체 처리, 설치형 네이티브 메시지부터 다운로드까지, 실제 강의 화면에서 KLAS Helper 동시 작동, GPU·최대 메모리는 미검증.
- 설정 캡처는 기존 브라우저 미리보기. 새 설치나 실제 Chrome 패널 실행 증거가 아님.

## Claude 검토와 판단

Claude가 이번에 완료한 흐름 검토는 열린 강의 조건·수동 처리·티켓·패널 닫힘 이후 상태·Shadow DOM 분리를 소스에서 검토한 결과다. 실제 Chrome 동작을 검증한 결과는 아니다.

Claude는 확인 OFF + 자동 처리 ON 시 별도 확인 없는 AI 호출을 문제로 지적했다. 이 동작은 사용자가 설정에서 직접 선택할 수 있도록 승인한 요구사항이다. Codex는 변경하지 않고, README에 사용량과 전송 조건을 명시했다.

요청한 프론트 레드·블루 추가 검토는 Claude CLI 실행 EPERM과 MCP 승인 차단 때문에 아직 수행하지 못했다. 새 브라우저 캡처도 접근 권한 거부로 진행하지 않았다. 이 결과를 검토 완료 또는 전체 흐름 통과로 표시하지 않는다.

0.1.2: start.cmd는 첫 실행에 설치한 뒤 공식 Extensions.loadUnpacked API로 별도 Chrome에 자동 연결하는 전용 실행 파일이다. 기존 0.1.0 PC 실행기는 이 방식으로 Chrome154 등록을 검증했지만, 새 포터블 실행기의 실제 설치·실행은 아직 미검증이다. 기본 Chrome 영구 설치와는 다르다.
